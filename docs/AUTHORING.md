# Authoring guide — implementing catalog IDs

This guide is for anyone (human or agent) implementing catalog briefs as real
animation modules. Read `docs/RUNTIME_CONTRACT.md`, `docs/VISUAL_STANDARD.md`,
`docs/LEGAL_CONTENT_POLICY.md` and `docs/ACCEPTANCE.md` first. The reference
implementation of all four treatments is the pilot motif
**LAW-0001..0004** in `src/animations/documents/` — read those files before
writing a new motif.

## Files per ID (paths come from the catalog `output` field)

| File | Content |
|---|---|
| `src/animations/<category>/LAW-xxxx.js` | Real scene: `export default defineAnimation({...})` |
| `src/animations/<category>/LAW-xxxx.presets.json` | ≥ 3 presets: `baseline-illustrative`, `contrast-or-alternative`, `long-labels-stress` (+ `baseline-es`) |
| `src/animations/<category>/LAW-xxxx.meta.json` | GENERATED by `node scripts/build-registry.mjs` from the module |
| `tests/animations/LAW-xxxx.test.js` | `contractSuite(id, {semantic, continuity, attach})` |

A motif's four IDs usually share a **motif kit** in
`src/animations/<category>/kits/<motif>.js` (geometry + pose solver only; each
entry owns its own timeline, layout and semantics). Never make an entry that is
another entry with a different title: story / mechanism / contrast / inspect
must be different compositions and timelines.

## Module shape

```js
import {defineAnimation} from '../../core/define.js';
import {makeMetadata} from '../../core/meta.js';
export default defineAnimation({
  id, version: '1.0.0', defaultDurationMs,
  metadata: makeMetadata({...}),          // title (en), titleEs (brief), category, motif, treatment, family, description, tags, assets
  sceneSchema: {...},                     // JSON-schema properties (use src/schemas/fields.js builders)
  defaultParams: {...},                   // fictional, illustrative, substantive
  strings: {en: {...}, es: {...}},        // optional scene-specific built-in labels
  scene: {
    sizes: {landscape: [w,h], square: [w,h], portrait: [w,h]},   // design spaces
    layout(ctx) { ... return L },         // PURE; may measure text (ctx.fit)
    build(ctx, L) { return vnodeTree },   // PURE virtual nodes (h/g), named dynamic nodes
    frame(ctx, L, u, timeMs) { return {nodes, semantic} },  // PURE per time u∈[0,1]
  },
});
```

Rules that tests enforce:
- `frame` is a pure function of (params, size, u). Once an attribute of a named node is animated, emit it in EVERY frame, using its build-time value when it is not changing. `applyFrame` only writes the keys present in the record, so an omitted key keeps whatever a previous seek wrote, and the render then depends on seek order (harness warning `dom-seek-order`). No clocks, no randomness
  except `ctx.rng(key, index)`, no state carried between calls.
- `nodes` maps **node names** (set with `name:` in `build`) to attribute
  records (`transform`, `opacity`, `d`, `x1`…, `stroke-dashoffset`, `text`).
  Unknown names throw. Names must be unique (prefix kit instances).
- `ctx.view.shape` is `landscape | square | portrait`, decided from the
  caption-safe content box. Adapt the layout (arrangement, stacking), do not
  just scale. The design space is fitted into the safe box; never draw text
  outside the design space.
- All user text goes through `ctx.fit()` + `textBlock()` / `chip()` /
  `caption()` (text nodes only). Honour `ctx.show('key' | 'all')`: with
  `textVisibility: 'none'` no `<text>` may be visible — the action must still
  read. Status words/letters count as text.
- Keep a readable held final state. Beat windows follow the brief.

### ctx (SceneContext)
`params`, `view` (`shape`, `content`), `design {w,h}`, `theme` (tokens:
`ink, inkSoft, fg, fgSoft, paper, paperShade, paperLine, card, wood, woodTop,
accent…accent4, accentSoft…, cloth[]`, `dark`), `t` (built-in strings),
`rng(key,i)`, `reduced`, `show(level)`, `id(local)`/`ref(local)` (instance-scoped
SVG ids for clipPaths/masks), `fit(text, {maxWidth,size,minSize,maxLines,weight,family})`.

If a motif needs new geometry, put it in the category `kits/` folder. Promote
it to `src/primitives/` only when a second category needs it, and then re-run
the tests of every dependant (evidence is bound to dependency hashes).

## Treatment requirements (from the briefs)
- **story**: actors/objects physically perform the concrete action. Props
  follow SOLVED hand positions; hand-offs happen at a shared point; nothing
  teleports. Final state = the supplied `finalState`, no legal conclusion.
- **mechanism**: decompose into components placed spatially for this motif
  (not a row of boxes), draw only explicit relationships with their kind
  (plain relation = no arrow; causal only when supplied), tracer follows
  `traversalOrder`, focus element enlarges, end with states visible.
- **contrast**: two complete scenes, identical except ONE changed fact that
  alters geometry/sequence (not only text/colour); side-by-side on wide boxes,
  stacked on tall; closing guide links the changed detail; neutral note; no
  winner, score or outcome.
- **inspect**: context → lens isolates the distinguishing detail (real copy at
  the same coordinates) → substitute one datum (`beforeValue`→`afterValue`),
  keep the old value traceable → return to context with a changed marker.
  Seeking back restores the old datum exactly.
  Lens checklist (from repeated review failures):
  - The lens is a REAL magnification: ≥ 1.5× the context in every preset × ratio. Crop it to the isolated detail rather than shrinking the context.
  - The lens is a real inspection, not a thumbnail: roughly ≥ 35–45% of the frame's short side, measured on the lens box's SMALLER dimension (min(w,h) / min(frameW,frameH) on the rendered box — LAW-0212 round 4), near its source, with its crop including the working space of the action it shows. If an object leaves the crop, the lens phase ends. It never shows an empty outline for more than ~200 ms (LAW-0688). The changed datum is shown in ONE place at a time: while the lens holds its copy, the context copy of that datum (its tag/value text) is hidden or reduced to a blank placeholder — not merely dimmed — and on open and close the hand-over is sequenced, never both legible (≥ 0.15 opacity) at once (item 4; LAW-0212 round 4, LAW-0696). The rest of the context may stay dimmed in place. Hide the context copy in step with the lens appearing (the gap between the context copy going and the lens copy being legible ≤ ~200 ms, and no stage state that reads as the after-value before the substitution beat) — civil-claim-01 LAW-0244. Magnification is measured against the context at REST (before any shrink), ≥ 1.5×. Portrait with a stacked lens (coordinator decision 2026-09-27, LAW-0232): the context ≥ 0.45 requirement may be met in either frame dimension, provided context + lens span ≥ 0.8 and context people stay ≥ 45 px. Measure the context share on what stays VISIBLE (not covered by the lens), not on the context group's bounding box.
  - The context stays a real scene during open and close, with no lone-thumbnail frames: it keeps ≥ ~45–50% of the frame width, dimmed in place or shifted, and context plus lens fill most of the safe box while the lens is open. The object whose value changes (record card, tag) stays visible while it changes (LAW-0688 round 3).
  - Nothing the rim would cut is drawn. Each supplied field is wholly inside the lens or wholly left out, never partly shown, and the changed datum's field is always wholly inside.
  - There is no double image while the lens is translucent over its source (item 4). A blank card is only needed while the lens actually overlaps its source; when the lens grows at a separate destination, fade the enlarged copy in as it grows (from ~40% open) and out as it shrinks. A bare blank rectangle must not stay on screen for more than ~200 ms, and must never cross the people (LAW-0168 round 3).
  - The new value is readable and still for ≥ ~400 ms.
  - The lens never covers a head or face.
  - Tested patterns: `tests/animations/LAW-0148.test.js`, `LAW-0160.test.js`, `LAW-0164.test.js` and `LAW-0172.test.js`.

## Semantics and tests
`frame()` returns `semantic` with meaningful, serializable facts: tracked
points `{x,y}` (for continuity), holder/state names, progress values,
`allReached` (all IK targets reachable). The contract test runs:
determinism (ordered/reverse/shuffled), frame mapping 24/30/60, invalid
inputs, presets × 16:9/9:16/1:1 layout (text inside frame & caption-safe
box), backgrounds/locale/labels/seeds/palette, injection, twin instances,
destroy/remount, continuity (60 fps, all ratios), attachments and your
semantic assertions. Write assertions that encode the brief's
`acceptanceCheck`.

Note: the content notice (`contentNotice: true`, the default) takes a band at the top of the safe area, so the design box is about 8% shorter than the raw safe area. Size design spaces for the box you actually get, and measure text in the browser, not by estimate. The contract suite lays out semantics only at 1920×1080. To check the real render in every ratio, use `tests/harness/supplied-text.js`:
- `suppliedTextSuite(id, {fields, content, captions})` checks that every supplied field is visible and un-truncated at the hold. It also checks that key text is ≥ 16 px (≥ ~19.5 px baseline) and never smaller than captions, and that the "no conclusion drawn" key is present.
- `identicalBeforeChange(id, changeAt)`, for contrast treatments, compares `semantic.lookA`/`lookB` before the change beat, with labels on and off.
`tests/harness/ratio-checks.js` → `ratioChecks(id, title, checks)` asserts semantic (`fn`) or DOM (`dom`) expressions in every preset × real ratio × labels on/off at the listed times. Do not copy these into per-motif files, and do not import helpers from another motif's test files. Never lower a floor (text size, scene share, coverage) or raise a limit (e.g. `continuityLimit` above 90 units per frame, reported as warning `relaxed-continuity`) in your own test to make it pass. An exception needs a coordinator decision, is limited to one named preset × ratio and to secondary content, and is written into the test with a comment citing that decision. Cite only decisions that were actually given, with their date and source (SESSION_HANDOFF); inventing a citation is an integrity failure. Otherwise, fix the layout.

## Defects independent reviewers keep finding (avoid them up front)
1. **Label collisions**: chips/callouts drawn over actors, props, other labels or the connector they describe. Place labels in free space with collision checks (graph.js does this for relation labels — pass `obstacles`, `bounds`, `separateLabels`), and check `automated.json` → `warnings` (`text-overlap`).
2. **Meaning lost to truncation**: author text cut to one line with an ellipsis. Give important labels 2–3 lines (`maxLines`), wider boxes or a restructured layout in the long-label preset; truncate only decorative text. The harness reports ellipsised text at the hold as warning `truncated-text` in `automated.json`; allow-list genuinely decorative text in the test with `allowTruncation: ['substring']` and a comment.
3. **Fake re-layout**: portrait/square showing the landscape design as a thin band (warning `low-frame-coverage`). Recompose: stack, re-orient the axis, enlarge the subject; the subject should use most of the caption-safe box.
4. **Garbled cross-fades**: old and new values fading in the same place. Fade the old one out (lifting it) before the new one fades in, or offset them. The same applies to placeholder bars or dashes: text that lands where filler bars are still visible reads as struck through. Fade the bars out first, or bring the card in as an opaque blank body and then fade its text in. The same goes for lenses: while an enlarged copy is translucent OVER ITS SOURCE, show it blank so two copies of the same text never overlap. Keep such blank phases brief, and show the copy whenever the lens does not overlap its source. See LAW-0155's text-over-bars test and LAW-0164's double-image test for reusable patterns.
5. **Connectors that don't land**: arrowheads ending in empty space, ends hidden under their own label, stubs too short to read. Anchor to real edges/ports, give connectors length, keep labels off the ends.
6. **IK artefacts**: elbow flips when a target crosses the shoulder line, forearms through faces, hands outside the reach (`allReached`). Choose bend sides per pose; keep targets reachable.
7. **Clipping by windows**: objects cut by the desk/stage clip in one ratio. Check every ratio's extreme positions.
8. **Detached annotations**: tags placed far from what they describe or left behind while the object moves. Parent them to the object's transform or add a leader.
9. **States shown too early**: a difference visible before the beat that introduces it (e.g. a contrast scene already missing the changed item at t=0).
10. **Tiny key labels**: names/roles below ~20 px at 1080p. Size key labels for mobile viewing.
11. **Subject in the top half only**: the scene sits in the upper ~55 % of a 16:9 or 1:1 frame with a blank band below, and its text shrinks to 14–17 px. The default `safeArea.bottom` (0.2) already reserves the caption band — check with `node scripts/shot.mjs ... --safe` and scale/recompose the subject to fill most of the dashed safe box in every ratio, with and without labels.
12. **Props parked on content**: a magnifier, pen or tag left resting over a card, label or track piece at the hold. Park props in free space and add a semantic test that the parked prop does not intersect cards/labels in every preset × ratio (including `textVisibility: 'none'`).
13. **Spanish/long words broken mid-word** (`devolució / n`, `(user-supplie / d)`, a lone `.` or `)` or a one-word widow on the last line): wrap only between words, and keep brackets and final punctuation with their word. The harness warns `orphan-fragment` for any wrapped line of 1–2 characters; if a word does not fit, widen the box, add a line or shrink within the bounded fit — test the `baseline-es` preset in every ratio.
14. **Editable fields that are never drawn**: a schema field such as `issues`, `assumptions` or `finalState` that exists but never appears on screen. The ending can then read as a conclusion, e.g. "the fact now meets the rule". Every customizable field must be visible somewhere, and reasoning scenes need a key or note that says states are "as supplied" and no conclusion is drawn.
15. **Labels-hidden variant leaking the difference**: with `textVisibility: 'none'` the layout changes, and a contrast/change state can show before its beat, for example a coloured or hatched part at t=0. Test the "identical before the change beat" rule in the labels-hidden variant too.
16. **Ambiguous connector routing**: two connectors running as a tight parallel pair, a line passing through another pin or along a row of features, stacked target pins. Each connector must be traceable from its source to its own target at a glance.
17. **Inverted text hierarchy under stress**: in `long-labels-stress` (especially 1:1) the layout shrinks the actual content (facts, rule/condition plaques) to 8–12 px while generic captions and element labels stay at 20+ px. Content text must stay ≥ ~16 px at 1080p and never be smaller than the generic captions: cap captions, widen plaques, draw shared content once (e.g. one rule plate for both contrast lanes) or recompose. Benchmark: accepted LAW-0091 keeps long-labels 1:1 facts at about 17 px.
18. **Text panels crowding out the scene**: fixing text size by shrinking the physical scene into thumbnails. For example, desks covering 11% of the frame while shared-text panels and result cards take the rest, or a 1–2 px cord. The action stays the subject. Draw shared text once as a compact strip, attach result text as callouts to where the action ends, and keep the acting objects large: each scene ≥ ~40% of the width side by side, full width when stacked.
19. **Rushed timing and empty transitions**: beats overlapping (a hand arrives while a rewind is still running), a rewind at 3× the forward speed, several return steps crammed into the last ~15 %, notes such as the neutrality key still fading in at u ≥ 0.95, or a transition that leaves only a small thumbnail on a blank frame for half a second. Run beats in sequence and complete the main action by about u = 0.8 (the briefs' hold beat starts at 0.73). Secondary notes may fade in during the hold, but everything must be fully visible for at least the last ~300 ms (harness warning `short-hold`; median of accepted items ≈ 500 ms). A host can hold the last frame as long as it wants with `seek(durationMs)`, so a long built-in hold is not required. Keep the context large during isolate/return transitions.
20. **Weakened stress preset**: shortening `long-labels-stress` texts so a layout fits, e.g. a passage shorter than in the baseline, or fewer items. The stress preset must stay at least as long as the baseline for every field (harness warning `weak-stress`), and should use near-maximum lengths and counts. Make the layout handle it: wrap, cap captions, share identical content, or recompose. Measure what renders (2026-09-26, courts-03): size and share assertions in tests must measure the RENDERED DOM (getBBox or getScreenCTM × computed font size, at 1080p) over all visible text, including keys, captions and headings. They must not read layout-model estimates, which can diverge from the render. Layout thresholds (2026-09-26; all shares are of the FRAME width or height, not the safe box): scenes stacked beside a right-hand text column keep ≥ 0.55 of the frame width (precedents LAW-0179 0.605, LAW-0191 ≈ 0.56); baseline-es is a baseline preset (≥ 19.5 px in every ratio); `create()` stays ≤ ~1 s in every preset × ratio, measured COLD in a fresh page (module-level caches don't count). Cards that turn or flip hide their text while it would render under 16 px. Standing coordinator rule (2026-09-26, from LAW-0687/0689–0692): if, after genuinely trying the fallback layouts (a right-hand text column with stacked scenes at 1:1, two-level or depth staging in portrait, shared content drawn once), near-maximum stress text still cannot fit at ≥ 16 px without scaling, cap that item's stress field lengths to the longest values that fit every ratio. Every field must stay strictly longer than baseline and counts must stay ≥ baseline. Record the measurements, and put a `coordinator decision` comment in the presets file and the test. Never render text below the floor and never change schema limits to make this work. DOM-less contract (2026-09-27): every module must import and `evaluate()` every preset without a DOM (text measured by the fallback estimator) and must never throw from layout — if no composition fits, return the best one with its `semantic.problems` flagged. Run `node --test --test-name-pattern="LAW-XXXX" tests/unit/core.test.mjs` for your IDs before reporting (accepted LAW-0183 and LAW-0696 were found failing it).

Harness help for items 2, 10 and 17: `automated.json` reports `truncated-text` (ellipsised text at the hold) and `small-text` (visible text under 14 px at 1080p at the hold, smallest first). Key content (facts, rule/condition text, names, states, tags) must not appear there. Genuinely decorative micro-text, such as simulated clause lines on a paper prop or FACT/RULE micro-tags, may be allow-listed in the test with `allowTruncation: [...]` / `allowSmallText: [...]` plus a comment saying why. An opaque overlay (a lens window or detail panel) may set `'data-occludes': 1` on its group. Text drawn earlier and lying fully under it then counts as hidden for the overlap, size and truncation warnings, so you never need to delay a lens (which would create an empty transition, item 19) just to satisfy the heuristic. Do not clear these warnings by swapping supplied text (any customizable field: names, hierarchy levels, passages, facts) for placeholder bars. Supplied content must stay readable, so make room for it instead. Bars are only for simulated filler text on props. `orphan-fragment` also flags a number torn from its word ("Day / 3", "paragraph / 23", "Language / 1"). Until the core `wrap()` keeps them together, keep such pairs together in your kit's own fitting. NOTE: core `wrap()` splits on `/\s+/`, which in JavaScript also matches U+00A0, so simply inserting a non-breaking space before calling core `wrap`/`fitText` does NOT work; wrap glue-aware in the kit (as `fitG` in `src/animations/causation/kits/prueba-contrafactual.js` and `glue()` in `src/animations/courts/kits/distribucion-de-sala.js` do), and check the `orphan-fragment` warning. Text size applies at EVERY moment, not only at the hold: any visible text (opacity ≥ ~0.3) must be ≥ 16 px at 1080p at every u. Elements that grow from a small scale (a card pulled from a cabinet, a scene regrowing after a lens) must keep their text hidden until it reaches the floor. The harness only checks sizes at the hold, so add a dense text-size-over-time test (see `tests/animations/LAW-0196.test.js`). `split-word` (warning): a wrapped line boundary splits a word that appears whole in the supplied text, e.g. "observació / n" or "COPI / A". The core `wrap()` still breaks a single word that is wider than the box, so give such words room, or step the size down (never below the floor) instead of letting them break.

## Legal content
Fictional names, `jurisdiction: unspecified`, `illustrative-unverified`.
Descriptive states only (sent/received, pending/signed, alleged/disputed).
Never invent rules, time limits, thresholds, outcomes, citations, or show
guilt/validity/winners. Hypothetical amounts are labelled as hypothetical.
Line styles carry meaning too: dashes mean "disputed / pending / ghost" across the library, so NEVER use dashes (or lighter strokes) to tell compared parties or routes apart. Use symmetric cues instead, such as letter badges and distinct solid markers (●/◆) with identical stroke weight (2026-09-26, causation-03). Words carry legal meaning too: never use "plazo", "deadline", "time limit" or "due" for a supplied span. Use neutral terms such as "response space as supplied" / "espacio de respuesta según lo aportado" (2026-09-26, civil-claim pilot). Implied structure counts as invented content (2026-09-26, courts-02). Shipped presets must not draw directed arrows between institutions or levels that read as an appeal, review, referral or competence route; use plain relations with neutral labels such as "linked as configured". A user may still configure a sequence link, but it is drawn with a visible "sequence as configured (illustrative)" caption. Hierarchies, levels and venues are always supplied and editable, with generic fictional defaults.
When two readings, positions or parties are compared, give them equal visual weight: the same size, opacity, stroke and contrast, and the same entry timing, with neither drawn over the other. Unequal treatment reads as endorsement. Glyphs carry meaning too. A tick/check mark or a green "OK" reads as approved/valid/correct, so use it only for neutral process steps such as "extracted" or "received". Mark a changed datum, classification or reading with a neutral glyph (Δ, pencil, dot). Never use a tick on a legal state, and never a cross on a party or a reading. Patterns carry meaning too: a × hatch, strike pattern or red wash on an area, card or person reads as excluded or crossed out. Use neutral fills (dots, plain tints, soft stripes). Colour carries meaning too: a red disc or a warning triangle reads as an alarm, so draw "changed" markers in the neutral accent used by the accepted inspect scenes (a white Δ on the blue accent2 disc — use `changedMarker` from `src/primitives/markers.js`). This applies to icon markers (discs, badges, pins) that signal a changed datum or a state. The outline or guide that points to the single differing fact in a contrast scene may keep the highlight accent the accepted contrast scenes use (e.g. LAW-0083's "only this row differs" guide). A/B scenario badges use their lane colours.

## Commands
```sh
node scripts/build-registry.mjs              # registry + catalog index + .meta.json
LAW_TEST_PORT=5201 PW_OUT=production/test-output/w1 npx playwright test tests/animations/LAW-0185.test.js
node scripts/shot.mjs --id LAW-0185 --ratio 9:16 --times 0.1,0.4,0.7,1 --out production/scratch/x.png
node scripts/qa.mjs --ids LAW-0185,LAW-0186      # evidence: contact sheets + review.json (not a review!)
node scripts/review.mjs --id ... --status pass|fail --reviewer ... --method ... --artifacts ... --findings "a|b" --content-ok
Visual-review integrity (2026-09-27): an image counts as viewed only if it actually rendered in the reviewer's context. If an image read returns "media removed", a request-limit notice or any placeholder, it was NOT viewed — say so, list it as unopened, and do not pass an item on images you could not see (courts-08 round 1 reported strips as opened that never loaded).
node scripts/accept.mjs --ids ...                # coordinator only: recompute lifecycle status in progress.json
```
Use a unique `LAW_TEST_PORT` and `PW_OUT` when several people/agents test at
the same time. Only the coordinator runs `accept.mjs` and edits
`production/progress.json` / `SESSION_HANDOFF.md`.

A screenshot counts as reviewed only when someone actually looked at it
(for agents: opened the PNG with an image-capable reader). Record what was
seen, including defects, with `scripts/review.mjs`.
